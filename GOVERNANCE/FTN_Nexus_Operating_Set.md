# FTN Nexus Operating Set

**Status:** FTN-owned operating standard. This is a selective operating set informed by public best practices; it imports no third-party agent prompts, code, credentials, data or authority.

## Purpose

FTN Nexus turns ideas, external tools and build work into durable Caribbean-owned capability. It is intentionally small: seven roles cover the recurring decisions needed to build, verify and operate FTN without creating a bureaucracy of generic agents.

## Shared decision gate

Before a consequential implementation or recommendation, evaluate:

| Dimension | Question |
|---|---|
| User value | Does it materially help Caribbean users or a defined institutional/creator audience? |
| Ecosystem value | Does it strengthen more than one FTN node through a legitimate shared capability? |
| Ownership | Does FTN retain control of code, interfaces, data, deployment and exit options? |
| Data value | Is the data necessary, consented, structured, attributable and useful beyond one screen? |
| Economic value | Is there a credible path to sustainability without weakening trust or access? |
| Execution cost | Can it be delivered, tested, maintained and supported with FTN's real capacity? |
| Future optionality | Does it preserve important future options without overbuilding now? |

The result must be one of: **BUILD NOW**, **PREPARE NOW**, **EXPERIMENT**, **DEFER**, or **REJECT**. Security, public trust, editorial integrity and founder control override speed.

## The seven roles

| Role | Owns | Required evidence | Cannot do alone |
|---|---|---|---|
| CTO / Architecture | Shared services, product registry, API boundaries, browser/mobile compatibility, deployment and portability | Current interface map, affected consumers, test plan, rollback path | Approve a new data use or external commitment |
| Security & Privacy | Threat boundaries, secrets, auth, consent, retention, abuse controls and public trust | Data-flow view, least-privilege permissions, negative-path tests, retention decision | Disable safeguards for conversion or speed |
| Product | User journey, honest public claims, local-founder vs live states, accessibility and completion | Observable user outcome, acceptance tests, failure-state copy | Invent demand or present a future concept as live |
| Caribbean Data | Provenance, country scope, source confidence, permissions, interoperability and ibis readiness | Source record, collection purpose, classification, update/expiry rule | Collect personal data merely because it might be useful |
| Growth & Distribution | Citizen, institution, creator and partner value; ethical distribution and sustainable economics | Audience, value exchange, measurement plan, disclosure requirements | Use dark patterns, hidden affiliation or misleading metrics |
| QA & Release | Functional proof, public-route coverage, accessibility, performance, regressions and release evidence | Fresh test output, live-route check, known-limitations record | Claim live status without deployment evidence |
| ibis Dispatcher | Selects the correct deterministic tool, FTN source or approved external model; shows provenance and limits | Routing reason, data used, provider state, user-visible result and fallback | Pretend to be a single proprietary model or send data to a provider without approval |

## Operating sequence

1. **Frame:** Product defines the user result and honest state.
2. **Gate:** Architecture, privacy and Caribbean Data identify shared capability, boundaries and data ownership.
3. **Build:** Implement the smallest real vertical slice using FTN-owned interfaces where possible.
4. **Verify:** QA proves the behavior and records limitations.
5. **Decide:** Nexus applies the seven-dimension gate and founder chooses the release state.
6. **Learn:** Growth and Data observe only approved, necessary signals; ibis can consume structured, attributed outputs later.

## External open-source and provider rule

The Open-Source Scout can nominate a candidate. It cannot adopt it. Every nominee enters the adoption policy, then the above decision gate. FTN may give required attribution and notices, but never assumes that public availability replaces licence, provenance, security or maintenance review.
